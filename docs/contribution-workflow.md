# Contribution Workflow

1. Create a branch from `main` for one scoped change.
2. Add or update tests before changing the behavior.
3. Run `pnpm check` with a supported Node release.
4. Record user-visible behavior and limitations in the pull request.
5. Request review for both frontend and backend changes when the API contract changes.
6. Address review comments with separate, readable commits where practical.
7. Demo the workflow using a non-sensitive Backstage entity and synthetic pull-request reference.
8. Update architecture or integration documentation before merge.

The repository is a portfolio project, so it does not claim participation in an organization's internal ceremonies, code reviews or deployment process.
